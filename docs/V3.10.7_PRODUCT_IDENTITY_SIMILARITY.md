# COBALT V3.10.7 — Generic Product-Identity Similarity

## Why this release exists
Live Similar Listings calibration exposed a recurring failure mode: listings could rank highly because they shared a marketplace category, vehicle/product context, seller template or generic product words even when they were not valid pricing comparables. Examples included RAV4 fuel-door/tailgate results beside an exterior door handle, Outlander window switches beside an ABS sensor, and OX492 beside OX730.

The opposite problem also appeared: left/right counterparts and relisted/exact products can be commercially equivalent even when one token differs. Cobalt therefore needs product identity rather than raw title similarity.

## Design rules
1. Candidate retrieval is intentionally broad internally; the Similar Listings UI exposes only trusted comparables.
2. Comparable acceptance is intentionally strict.
3. Explicit contradictions subtract confidence. Missing data does not.
4. Exact distinctive identifiers are strong evidence.
5. Seller/marketplace boilerplate must not make incompatible SKUs look identical.
6. Category is context, not identity.
7. Complementary paired variants such as left/right may remain strong pricing comparables when the rest of the identity agrees.
8. The core matcher is category-agnostic; no vehicle make/model tables are required.
9. Low-confidence candidates cannot influence peer corroboration, Opportunity-family evidence or pricing.
10. Raw observation history remains independent from similarity so future matcher calibration can be replayed over existing data.
11. Known relists and exact same-title listings from one seller count as one independent Opportunity evidence unit, even though their raw observations remain separate.

## Live calibration fixtures
- RAV4 MXAA52 right-front exterior door handle ↔ left-front counterpart: accept strongly.
- RAV4 exterior door handle ↔ fuel door/tailgate: reject.
- Vitz SCP90 52-183 right headlight ↔ 52-183 left headlight: accept strongly.
- Vitz 52-183 ↔ 52-169: reject from pricing due reference conflict.
- Outlander CW5W right-front ABS sensor ↔ left-front ABS sensor: accept strongly.
- Outlander ABS sensor ↔ CW5W window master switch: reject.
- Colorado RG 4-button ↔ 2-button master switch: discoverable variant, but reject as the same pricing product.
- PARTSNZ 84820-60080 ↔ 84820-60120 seller-template titles: reject as the same product.
- OX730 across Outlander/ASX/Lancer wording: exact OX730 identity can outweigh model wording differences.
- OX730 ↔ OX492 and OX730 oxygen sensor ↔ MP163 MAP sensor: reject.
- Toyota Hiace master window switch ↔ Nissan Note master window switch: reject.

## Operational expectation
After deployment, let the ordinary observation worker continue collecting raw listing snapshots. No database migration or historical-data rewrite is required. Similarity/comparability is recomputed from listing evidence, so later calibration can use newly accumulated observations without losing raw data.


## Sourcing notification consolidation

The sourcing-opportunity bell presents durable opportunity state rather than a raw event log. Multiple `opportunity_notifications` rows for the same `opportunity_id` remain stored for provenance but collapse to one feed row. The feed uses the current opportunity metrics and latest event time, and indicates how many signal updates were consolidated. Opportunities are never merged by display title alone, so distinct product families with the same human-readable title remain separate.

The default feed is **All**, with filters ordered **All → Source now → Strong → Early**. The former Priority shortcut is removed. Opening an aggregated row marks that opportunity's notification history read without deleting historical events. Repeated notifications are presentation history only and do not independently increase opportunity strength.

## Seller/product evidence units

Commercial corroboration and pricing now count a high-confidence product identity from the same seller once, even when that seller publishes multiple compatibility/search-facing Trade Me listings. The raw listings and their observations remain independent for marketplace-demand analysis. Relist lineage remains deduplicated as before.

This prevents one seller with many titles for the same SKU from masquerading as multiple independent market offers, while retaining the useful demand signal from each listing's separate exposure.
