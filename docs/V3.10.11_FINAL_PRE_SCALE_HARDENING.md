# COBALT V3.10.11 — Final pre-scale hardening

## Why this release exists

The 2026-09-10 DB export showed that the Opportunity engine could admit commercially different
parts into one high-confidence family even though the individual Observation Queue rows were
reasonable. Examples included Vitz quarter glass inside a RAV4 door-handle family, and wiper,
window, indicator and headlight components inside switch families.

V3.10.11 fixes the family boundary rather than changing sourcing thresholds.

## Family admission invariant

A listing contributes to a corroborated Opportunity only when:

1. the marketplace-neutral similarity gate considers it a trusted comparable; **and**
2. high-confidence product identity is compatible with the family representative.

Recognised component conflicts are hard splits. Make/model conflicts are also hard splits unless
shared part-number or chassis evidence proves common fitment.

Generic fallback product phrases remain soft so Search Terms can scale across non-automotive
categories without requiring a hand-written taxonomy for every product.

## Durable link reconciliation

`opportunity_listings` is now reconciled to the current computed family. Links that are no longer
members are deleted, so historical contamination cannot remain attached to a manually sourced or
otherwise durable Opportunity.

`similarity_to_family` now stores the actual similarity score and each family link records
`identity_compatible`, making future DB exports auditable.

## Thresholds

V3.10.11 does **not** loosen Opportunity demand/stage thresholds. The purpose is higher precision,
not more alerts.

## Production access gate

UI pages are protected by a four-digit access-code gate. The PIN is validated server-side and the
browser receives an HttpOnly persistent cookie. Set:

- `COBALT_ACCESS_PIN=5623`
- `COBALT_ACCESS_SECRET=<long random secret>`

in Vercel Production environment variables. Do not commit either value.

The gate excludes `/api/*` so the existing scheduler, ingestion and observation token workflows
continue unchanged.
