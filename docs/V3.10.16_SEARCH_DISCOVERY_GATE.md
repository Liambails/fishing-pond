# V3.10.16 Search Discovery Gate

## Purpose
Search terms such as `AQUA NHP10` can return both car parts and complete vehicles. Complete vehicles are not sourcing candidates and must not enter the Observation Queue.

## Gate
The gate runs on rendered Trade Me search results before `upsert_discovery`. A result is ignored when any of the following applies:

1. Its Trade Me URL is a strong complete-car path (`/a/motors/cars/` or `/a/motors/used-cars/`).
2. The largest visible price on the result card is at or above `SEARCH_WATCH_MAX_LISTING_PRICE_NZD` (default NZ$5,000).
3. The title/card has strong whole-vehicle metadata (year plus vehicle descriptor, or several vehicle descriptors) and the title does not identify a component.

Component vocabulary includes common parts such as switches, headlights, sensors, engines, transmissions, mirrors, panels, brakes and many other automotive components. This protects part listings that contain vehicle fitment words.

## Frictionless behavior
Rejected results are deliberately not treated as errors. They:
- do not create or update a listing;
- do not receive `next_observation_at`;
- do not create an acquisition failure;
- do not appear in the Observation Queue;
- do not create an intervention/error message.
- if the same result was queued by an older Search Watch release, a later sighting quietly deactivates that search-discovered row; manually/own-added listings are never touched.

Search-run diagnostics retain only aggregate filtered counts and reason codes for auditing.

## Price ceiling
Default: NZ$5,000. Override in the worker environment if needed:

```bash
SEARCH_WATCH_MAX_LISTING_PRICE_NZD=5000
```

The threshold is intentionally a discovery ceiling, not a valuation claim. It prevents high-value whole vehicles and similarly expensive noise from consuming observation capacity.
