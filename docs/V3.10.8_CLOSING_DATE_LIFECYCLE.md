# COBALT V3.10.8 — Closing-date and lifecycle reliability

V3.10.8 makes Trade Me closing time a first-class lifecycle signal rather than a display-only field.

## Root cause fixed

The collectors were already finding Trade Me close strings in almost every observation, but the Python worker normalizer only accepted formats such as `Wed 9 Sep, 4:00pm`. Trade Me commonly renders a space before `am/pm` (`Wed 9 Sep, 4:00 pm`) and closed-page variants such as `Closed: Mon 7th Sep, 9:54am`. Those raw values were preserved in `raw_snapshot` but normalized `observations.close_date` was often NULL.

The latest DB export used during this fix contained 1,566 observations. 1,556 raw snapshots contained a close value, while only 655 normalized observation rows did. The V3.10.8 parser successfully normalizes all 1,556 stored raw close strings in that export.

## Collector changes

Worker and extension collectors are now v1.5.9. Close retrieval uses, in order:

1. known Trade Me motors/marketplace closing components;
2. semantic closing-time test IDs/classes and date-bearing attributes;
3. JSON-LD `priceValidUntil` / `availabilityEnds`;
4. explicit close/end keys in structured script state;
5. an explicitly labelled rendered `Closes` / `Closing` / `Ends` fallback.

The page-text fallback requires an explicit close label so unrelated dates cannot become closing dates. Active captures with no close value now receive a non-fatal `missing_close_date` extraction warning.

## Normalization

`worker/close_date.py` normalizes NZ-local Trade Me formats including ordinal dates, optional spaces before `am/pm`, date-first/time-first layouts, `Today`/`Tomorrow`, `Closed:` prefixes and year rollover around New Year. The TypeScript manual-ingest normalizer mirrors these formats.

All normalized values are stored as ISO timestamps in UTC.

## Lifecycle use

A known future close date is used to schedule a confirmation shortly after expiry. When that check observes a closed listing, COBALT enters relist-watch state as before.

COBALT now also compares the observed closure time with the *previously advertised* close time. A listing is only marked `sold_early` when:

- a prior observation advertised a later close time; and
- Trade Me provides explicit sold evidence; and
- the listing is observed closed at least five minutes before that advertised time.

Early closure without explicit sale evidence is neutral because it may be a withdrawal or removal.

Confirmed same-seller relists are stored in `final_evidence.relist`. Opportunity Intelligence can use confirmed early sales as strong lifecycle demand evidence and same-seller relists as weaker continuity evidence. Relisting alone is not treated as proof of a sale.

## Backfill existing data

Run the new backfill once after deployment:

```bash
cd ~/cobalt
source worker/.venv/bin/activate 2>/dev/null || true
python3 worker/backfill_close_dates.py
python3 worker/backfill_close_dates.py --apply
python3 worker/reseed_expired_due.py
```

The first command is a dry run. `--apply` only fills NULL `observations.close_date` values from already-stored raw snapshots; it never overwrites an existing non-null close date. `reseed_expired_due.py` then makes active listings whose newly recovered close date has passed immediately due for a normal worker confirmation.

Active listings will also receive correct close dates naturally on their next V1.5.9 observation, but the one-time backfill is recommended because it restores historical lifecycle context for closed/relisted listings too.
